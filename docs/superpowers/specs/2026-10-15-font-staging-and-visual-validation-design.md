# Original font staging and rendered visual validation

Status: ADOPTED verification-contract amendment, explicitly approved by the human
on2026-10-15: conservar originales y validar el acabado. This replaces only the
requirement for proof of the exact renderer-selected file. It does not change
the authored appearance, original font bytes, layout, effects, timing or model
vision. It does not authorize implementation/runtime tests by itself;6b's later
exact ownership/brief and separate actual qualification budget still govern.

## Preserve originals and measure the frozen staged files

Use the current registered Impact title and Arial Bold subtitle assets. No font
renaming, name-table edits, subsetting, derived fonts, alternative faces, global
installation, driver/PATH change, new renderer/build or native hooks/debugger.
Do not embed font files in the delivered MP4 or redistribute them with it.
Local job staging remains private on this machine, not cloud/server transfer.

Before any measurement, verify the required registered original identities and
stage byte-identical job-private copies. Hash staged bytes and freeze their
manifest/registry. Measure, glyph-check, wrap and compile from that SAME staged
registry, not from a live source path later. Required IDs remain headline_impact
and subtitle_bold; original face/index/style metadata are preserved. Reject
missing/foreign/changed assets and unsupported glyphs; no silent substitute.

The existing serializer, title fitting cap46, authored subtitle size/bold/colors/
outline/active-word behavior, destinations, line packing, ASS timing/global z and
literal escaping remain unchanged. PNG branding is unaffected. A hash-derived
staged filename is permitted; internal font names/bytes must not change.

## Distinct evidence, never a single verified-font flag

Later contracts/metrics must distinguish:

- registered original identity and actual staged path/byte count/SHA256;
- measurement-file identity and face index from the frozen registry;
- observed renderer family/provider/fallback diagnostics, with their scope;
- selected_file_identity_status='unverified'; no selected-file SHA inferred
  from a family name, a load message, same pixels or a separate font lookup;
- decoded visual checks and their actual observations/thresholds/findings.

Do not use fonts_verified=true to erase those distinctions. A missing source or
stage hash is not excused by this amendment. It waives ONLY selected-file byte
attestation; it does not waive visible correctness or unsupported-glyph/fallback
handling. Unexpected visible font/fallback/style behavior must fail or remain a
reported unresolved visual issue, never silently presented as matching.

## Rendered acceptance remains required

Under the later separately bounded actual gate, inspect independent decoded
frames for text presence/readability, expected bold/upright appearance, intended
font style, fitting/wrapping, containment/safe regions, outline/colors, active-word
state and authored activation/z-order. Check boundary and representative frames
using independently stated expectations, not only compiler boxes or name logs.
Keep compiler_resolved measurements separate from decoded_observed facts.

Passing those checks is evidence for the tested visible result, not a proof of
which exact font bytes libass selected or a universal guarantee for future text.
Per-job staged/source integrity, supported-glyph checks and truthful diagnostics
still apply. Model/editorial/human acceptance and overall render/encoded-A-V/
performance gates remain unchanged.

## Rationale and authority

Root read the complete primary-backed font proposal and independently checked
current upstream libass/FFmpeg source. Name-only selection logs can be ambiguous;
current-source facts do not establish provenance of the pinned build. The human
chose original fonts plus visual validation instead of more work on exact-file
attestation. No observer/instrumentation or weaker byte-identity claim is hidden
in this decision. No font modification rights are assumed.
